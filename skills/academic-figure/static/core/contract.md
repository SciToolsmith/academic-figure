# 核心契约

## 目标

在保持科学含义、不越过证据边界的前提下，将科研数据转化为适合论文沟通、可复现、可审查的图形；必要时，建议与数据和研究问题更匹配的视觉表达。

## 不可越过的边界

- 不编造观测、效应、P 值、置信区间、样本量、富集结果或科学结论。
- 不因某个案例好看，就忽略观察单位、配对/重复测量、层级、删失、空间依赖或组成约束。
- 不在未说明的情况下更换原数据、丢弃样本、改变统计口径或篡改阈值。
- 不把参考图的面板数、行列布局、标签、配色或结论当成必须复制的内容。
- 不把“符合 Nature 水平”当成可自动保证的结论。可以审查投稿适用性，但接收与科学正确性仍需作者、统计人员和审稿人确认。

## 数据使用

- 有真实数据：使用真实数据，保留未修改源文件，记录字段映射、类型转换、排除和缺失值处理。
- 无数据但用户要演示：可使用中性、可复现的模拟数据；模拟状态在回答、代码、文件名或交付说明中明确，不默认写进投稿图画布。
- 真实数据读取或验证失败：停止并说明问题，不静默切换为模拟数据。
- 字段含义不明且会改变图形决策：先询问，不根据列名猜科学含义。

## 成图文字边界

- 用途未说明时，生成或重构任务默认采用“投稿清洁画布”：只保留解释科学证据所必需的轴、单位、图例、面板编号/标题、数据标签和必要统计或方法标记。
- 方案名称、选图理由、配色说明、工具包/版本、随机种子、模拟声明、文件路径、运行方法、验证计数和 QA 结论属于工作流或溯源信息，放在回答、代码、图注草稿或交付说明中，不进入投稿成图。
- 不承担证据解释功能、且移入图注后不影响独立理解的总标题和解释性副标题，投稿时默认移出；承载队列、比较对象、时间窗、单位或统计口径的内容按 `evidence-facing` 保留或压缩。
- 同时提供多个候选方案时，各候选图单独清洁导出；需要比较时另做可带方案名称的对比预览。不得删除读图所必需的科学注释来追求表面简洁。

## 简短图形契约

编码前用自然语言确认：

1. `question`：图要回答的问题。
2. `unit`：一个点/行/样本代表什么。
3. `design`：独立、配对、重复测量、层级、空间、生存/删失或组成数据约束。
4. `evidence`：原始值、汇总值、效应与区间、模型输出或关系结构。
5. `message`：读者首先应读到的信息。
6. `use`：投稿、汇报、教学、探索或其他用途。
7. `backend`：Python、R 或只审校不生成代码。
8. `text_language`：成图可见文字的语言及其判断来源。
9. `delivery`：最终尺寸和输出格式。

契约是工作纸，不是要求用户填写长表单。已知信息直接提取，只追问真正影响决策的缺口。

## 隐私与开源边界

- 用户面向输出不披露私有源码路径、未公开文件名、内部模板 ID 或私有工作材料来源。
- `atlas` 层案例只代表图鉴、元数据和通用提示词可用，不代表完整源码已开放。
- 只有索引中 `openImplementation.<language>` 为 `true` 时，才可声称有该语言的开放实现。
